# UX redesign: decisions for the player to review

Made by Claude during planning (2026-11-26) with the player's delegation; revised after the three plan reviews (the same day). Each is held as the default; the build proceeds on it unless you change it. Ordered by how much a wrong call would cost. Plan-level decisions are added below the program ones by each plan.

Format: **decision** · why · alternative · cost if wrong / how to reverse. **"Changed after review"** marks a row whose decision differs from the first draft; the list is repeated in full at the end.

Canonical ids: program decisions are D1–D11 and R1–R28 (ux-program.md §7); plan-local ids (UF-P#, UF-D#, UA-D#, UH-D#, UT-D#, UD-D#, UE-D#, FT-D#) alias into this sheet. Aliases: UF-D2 = UF-P7, UF-D3 = UF-P1, UF-D4 = UF-P3, UF-D6 = UF-P10. Every decision in every plan is listed in that plan's own table; this sheet carries the ones that cost most if wrong.

## Questions only you can answer (defaults held, nothing waits on them except where noted)

1. **Anchor approval (UX-G1):** the one art gate. At real phone size, which paint finish, Pell silhouette and figure scale read as your game? Default: the bible's flat brim and the smallest scale that keeps each person recognisable. Code proceeds while you decide; only *scaling* art waits.
2. Pell's hat: flat brim (bible, lampwater study) or flat cap (seam study)? Default: flat brim; the anchor sheet settles it.
3. **Masters and repo size (D4):** after the pilot shows measured source and clone sizes, do you want a self-contained Git history that carries every accepted native-resolution source, or a backed-up art archive with hashes in Git? Default: commit only accepted native sources; switch to the archive if the pilot projects over 300 MB.
4. **Handwriting face:** does the apprentice need a distinct handwriting face next to the owner's script and the reading serif? Default: no, two faces; asked only if the rendered 14 px sample shows Pinyon fails.
5. Should the going-out plate play on browser Forward to the Map? Default: deliberate doorway navigation only.
6. Is a blocking rotate prompt part of the notebook experience? Default: no, landscape stays playable (inline hint at most).
