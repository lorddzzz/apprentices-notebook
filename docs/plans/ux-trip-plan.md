## 2. Proposals

- **UT-D1 Threshold keeps its meaning.** The board frame says "before a heart room", but the real `Threshold.svelte` is the barred-gate try-it room reached from a heard district's "Try the lock" on the map (`flow.ts` line 116, `planThreshold`). No pre-heart screen exists and none is added. The frame is applied to the real thing: **two stages on one route**: (1) intro page: district banner (art slot, `DistrictBanners` fallback), rule card (`room.goalText` + `room.note` + a pictogram), a read-only preview of the room board, **Enter** primary; (2) the live room (today's `BattleView`) with the city header (← Leave, Retry as the ⋯ neighbour). **The intro stage resets on route or room change and on Retry** (Retry returns to the live room's start, not the intro, but the intro shows again after Leave and re-entry or a different `?d=`); the preview and the live room use **the same `BattleSession`** (the preview is the session's initial state, read-only), so Enter starts exactly what was shown; **victory still writes `solveThreshold` immediately** (before any moment of "The gate burns"). The canals' composite goal (and any compound/extension goal) uses an existing neutral goal pictogram; the authored `goalText` already states the exact challenge. *Redefines: board frame "Threshold (before a heart)".* *(changed after review)*
- **UT-D2 No ??? on offers.** Hiding an offer's identity makes the pick blind and unfair (G2). Instead the gold ribbon "New" marks a find the notebook does not have: rune ∉ `profile.known`, method ∉ `profile.methods`, solvent ∉ `profile.solventsFound`, recruit ∉ `household.members`; ink, vellum, doorway, key never. Pure function, no save change. The ribbon is gold only for a find the notebook really does not have; **selection uses its own cue** (edge and check, not the gold ribbon). *Redefines: Loot frame "unseen kinds ???".* A "???" for never-met kinds needs a new save field; left as a follow-up.
- **UT-D3 Wiped data stays in memory.** `WipeSummary` (`flow.ts`) is app state only (`game.wipe`), not in the save, and the Wiped screen already does not survive a reload (it lands on the Study; the trip page reads `lastTrip`). Keep that. Extend `WipeSummary` with optional `rooms`, `cause`, `final` (the last `BattleState`), built in `endBattle` from the **incoming trip** (current encounter index and completed-fight count), `battle`, `log`. **No save change; `final` is never serialised** (test: reload with `lastTrip` intact and no final board in the serialized save). "See it" builds a read-only `BoardView` with **`viewOf(final)` (`src/app/view.ts`)**: no actions, no tap handlers, no misleading focus targets, rendered through FT's board component. It ships once FT-8's five-layer board is on main; **gate: FT-8, or an explicit later integration task (UT-10) named in the status file**; until then the button is hidden. *(changed after review)*
- **UT-D4 "What went wrong" is attributed, never invented** *(changed after review)*: `wipeCause(final, log)` looks at the **terminal events tied to the last party casualty** (the foe attack, hazard, burst or party-harm effect that took the last standing party unit down, with its supporting events in the same chain) and phrases one sentence in the log's voice (`describeLog`). When no cause can be proven from the events, it returns a **neutral observed-loss line** ("The party fell in the {place}." built from the room name and the last events' plain description), **never an invented cause** ("They ran out of room to move." is removed). No new content table.
- **UT-D5 A line per room actually fought** *(changed after review)*: `wipeRooms` lists only rooms that were actually played: for a run that started at a checkpoint (`src/engine/trip/start.ts` can start past room 0) the list begins at the start index, not at 0; for consecutive encounters it uses the **current index and the count of completed fights in the incoming trip**: cleared for each completed fight, `fell` for the current one. Tests: a checkpoint-start first-room wipe (one line, `fell`), and a start-from-zero run that crossed the checkpoint (all rooms listed). Not per-foe.
- **UT-D6 Transitions are UH's.** Set out and Home keep calling `game.setOut` / `game.returnHome` unchanged; UH wraps them at the router layer. UT adds no transition code, only a one-line `markNavigation(...)` call (UH-D6's navigation signal) in the Home handlers of Cleared and Crossroads and in Wiped's *Read the trip* handler, once UH-13 has merged (UT-11, below). Crossroads' Go home also calls `game.returnHome()` and goes directly to the trip page, so it plays the full-lamp plate.
- **UT-D7 Crossroads primary** = Push on filled, Go home outlined above it (board proposal). When Push is absent (cleared) Go home is primary. Span choices and doorway "through" ways render as choice cards (92 px), all of `CrossroadsView.ways`, with their disabled reasons and warnings. **`CrossroadsView.home` stays separate from `ways`** (including its disabled reason); several district ways may exist without a Push action, and nothing is inferred from a way count. *(changed after review)*
- **UT-D8 Map raster and vector share one coordinate system** *(changed after review)*. The vector layer is `MAP_PAGE_HEIGHT = 1900` CSS px (`src/app/city.ts`), so a 1:1 @2x raster is **750×3800** (C4, UA-17), not the board's 750×2400. Width 100% with an intrinsic aspect ratio gives 1900 CSS px tall only at exactly 375 px of *page* width, and Map has padding and the tablet column can reach 480, so: **the base layer is pinned to the node layer's actual width × 1900 CSS px at every width (375, 430, the 480 column)**, and **one transform applies identically to the base plate, every ink crop, the paths and the marks**. Crops use top-left bbox units in **750×3800 master pixels**; UT consumes the **art metadata module** UF adds in `src/ui/art/` (build-time, compact: per art id, size and bbox/offset; C2's `artUrl` returns only a URL). The growing under-Seam content (`mapPageHeight` with `underSeam`) stays below, in its existing slot, outside the plate. UA-17/UA-25 deliver **cropped alpha WebPs** (updated in the UA briefs by the art fixer). Until art lands: paper tile. *Redefines: the board's map size.*
- **UT-D9 Ink-in** is a 400 ms `--dur-base` opacity and stroke reveal **only for the fresh reveal** (districts in `freshOnArrival`); **known ink stays visible on every revisit** (rendered plain, never re-animated); reduced motion: instant. One overlay per district is optional art (`map/city/ink-<districtId>`, UA-17; Underjoin's comes from UA-25); without it, the vector mark and caption ink in. *(changed after review)*
- **UT-D10 Rumoured = pencilled** is the existing `heard` state (dim, dashed, blurred dot), restyled. Unheard districts draw nothing. **No single "next unheard" ??? mark** (the first unheard in id order need not be the next unlock, and hidden under-Seam entries have coordinates too): `frontierMarks(profile)` returns a mark only for a **genuinely visible frontier** (a district that is visible and attached to the visible path but not yet heard, per the map's own visibility rule); **default: leave the paper blank**. Both `hearsAs` entries (`city.ts`) are excluded from ordinary frontier marks. Pure function in `tripUx.ts`. *(changed after review)*

## 3. Current implementation and risks

- `Map.svelte` (192): dark `--wall` frame, own header, a 1900 px parchment page with an SVG path layer (`mapPaths`) and absolutely placed `DistrictNode`s (% positions, `label` side, 150 px captions). It opens scrolled to the bottom (the Seam sits low) then centres the freshest node; page grows with `underSeam` (lower Seam stair, inked pages, owner's door) via `mapPageHeight`. District pieces plug in through `DISTRICT_UI` (`mapSheet`, `lowerSeam.underNode`, `inkedPage.underPages`, `solvedArt`). `SetOutSheet` (229): hint, carried spells, start-point radios (checkpoint), drawn-page facts, tuned line. Risks: tap targets over art (node name buttons ≥ 44 px), scroll restore, the under-Seam slot grows beyond the raster (D8).
- `Threshold.svelte` + `threshold.svelte.ts`: one `BattleSession` ('lab' mode), `thresholdStart`, win writes `solveThreshold` at once, "The gate burns" moment. `ThresholdSpec` has `goalText`, `note`, `solvedArt`.
- `Loot.svelte` + `OfferCard` + `lootviews.ts` (`cardPlan`: core, registered key, fallback) + `TripStatus` + `CardFace` (district cards, `ui/districts/cards`). Card is 88–150 px, uses `Button`/link mix. Risk: district offer cards draw their own body; the new card shell must host them (art left, text right) without a district edit. Settle first in UT-5 (UT-7). Longer offers keep scrolling, the bonus-pick flow, selected-index reset and paper/term text; the 112 px, three-cards-visible figure is a baseline, not a cap.
- `Crossroads.svelte` + `crossroadsView` (`WayView`: label, note, sub, warn, disabled, testid) + `CrossroadsChoices` + `LootChips`. Seam and canals add `crossroadsNote`, others `crossroadsLine` (Cleared).
- `Cleared.svelte`: lower Seam heading/line vs `clearedHeading(trip)`; `Return home with N finds`.
- `Wiped.svelte`: `wipeLine(encounter)`, lost chips, learned list (`namedTitle`), "Read the trip" (→ `#/trip-page`) and "Back to the study". The summary holds only the last room name, lost loot and learned ids.
- Tests that must keep passing: `tests/app/{crossroads,flow,tripviews,threshold,city-map,lower-seam-map}.test.ts`; testids on these screens are used by sims and scenario tests: **keep every existing `data-testid`**.
- Riskiest unknown: the `WipeSummary` extension and `final` state (UT-2) and FT's read-only board API (UT-9). UT-1/2/3 go first and need no UF.
