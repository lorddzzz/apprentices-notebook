# Household core: open roster, trip slots and start points (HC)

> Design: [party.md](../design/party.md) §0b–§1 (§0d wins over §0b/§0c), [DESIGN.md](../../DESIGN.md) §6.1, §6.2, §6.4. Roadmap: **BL-129** (part of BL-43). Brief: [build-program.md](build-program.md).
> **State: Drafted (not approved).**
> Scope: replace the fixed Draughtsman/Stoker pair with an open household of apprentices, clear incompatible saves, pick 1–3 apprentices for a trip on a household shelf in the Study, and play every room (trip, threshold, Lab) with that party on per-room boards whose start points are drawn from the trip seed.

## 1. Scope and settled rules

**Delivers**
- An **apprentice registry** in `src/data/` with the kit party.md §0b names: body (HP, move), one basic action id, school lean (trained/gifted), one habit id, a starter page, token letter, colour and shape. Only the pair has entries after this plan; RC adds seven, AH adds the actions and habits.
- A **household** in the profile: who has joined (in join order) and three trip slots. One operation, `joinHousehold`, adds an apprentice on the bench with their starter page (§0b "Joining apprentices land on the bench").
- The **breaking save change**: a new save version; anything older is cleared, not migrated (§0c "Saves"). A fresh save holds the pair and an empty bench.
- The **household shelf** in the Study: portrait cards, three trip slots on top, a bench below, tap a card to open that apprentice's page, tap or drag to fill a slot, locked during a trip (§1 "The household shelf and trio").
- **Party size 1–3 everywhere** in run and battle, with no scaling and no bonus (§0b "Fewer than three"): same rooms, same loot, fewer casts.
- **Per-room board sizes** (about 5×6 to 7×9) and **at least four start points per board**, the party's spots drawn each time from the trip seed through `engine/rng`; a smaller party takes a subset (§0b "Board size", "Starting spots", §1 "Start points and boards").
- The **board notation for start points** instead of named `D`/`S` tiles in room data.
- **Mechanical conversion** of today's 12 Seam layouts, 15 canal layouts and the canal lock to start points. CN and SM re-author rooms later; this plan only makes the current ones work.
- **Threshold rooms** played by whoever is in the slots (§0d).
- **Apprentice tokens** (letter, colour, shape) on the board, the party strip, the trip status, the trip ledger and the trip page; the **Lab** can field any apprentices from the registry.

**Leaves out** (owner in brackets): Pull, Hop and Swap and the seven new habits (AH); the seven new apprentices' data, recruit offers, preconditions, guaranteed pages, door arrivals, codex presence (RC); re-laid rooms at new sizes (CN, SM, district plans); trip-shape hooks and new offer kinds (DK); arrival rules for actions (FD). The "copy page from…" helper stays out (§0c).

## 3. Current implementation and risks

- `src/data/types.ts`: `MemberId = 'draughtsman' | 'stoker'`, `MemberDef` with `shape`/`startLattice` (fixed-geometry relics), `HabitId` (includes a test-only `bindOnTile`). `src/data/members.ts` holds `MEMBER_IDS`/`MEMBERS`. `TUNING.grid` (6×8) is unused.
- `src/engine/run.ts`: `perMember` builds `Record<MemberId, …>` for `inkCapacity`, `lattices`, `proof`, trip `hp`/`charges`; `startTrip`, `beginEncounter`, `finishEncounter`, `carryCharges`/`applyDoorway`, `recordTripCasts`, `compileGlyph`, `rollOffers` (ink picks a member), `parseSaveData`/`validateSaveReferences` (`oneOf(MEMBER_IDS, …)`) all loop over both members. ~40 uses; the largest single refactor.
- `src/engine/notation.ts` `unitFor`/`parseCell`/`parseBoard`: members come from tokens; duplicate-member check. `src/engine/battle.ts` `createBattle`/`spawnMember`/`createEncounterBattle` spawn whatever tokens the board names; `BattleSpec.party` overrides by id. Board size is already free in the engine (`width`/`height` from the board).
- `src/app/save.ts`: `CURRENT_VERSION = 8`, v7 via `legacyV7.ts`, `<7` → `OlderEditionError` → new game + notice. Bumping the floor is cheap.
- `src/app/threshold.ts` `thresholdStart` fields `MEMBER_IDS`; the lock board in `src/data/districts.ts` names `D` and `S`.
- UI: `LatticeEditor.svelte` bookmarks iterate `MEMBER_IDS`; `UnitToken.svelte`, `PartyStrip.svelte`, `TripStatus.svelte`, `TripPage.svelte`, `OfferCard.svelte`, Lab `Palette.svelte` use `--member-<id>` CSS vars; `BattleBoard` scales a viewBox, so 7×9 cells shrink to ~47px at 375px (tap target risk, still ≥44px).
- **Risks:** (1) blast radius: ~100 test files name the pair; fixtures must keep working with fixed `D`/`S` boards (P3) and a helper for profiles. (2) `run.ts` is also touched by FD, DK and RC; HC-1/HC-4 must land before DK splits `run.ts`, or DK-W0 must carry `Trip.party`. (3) Random spots can make an old room unfair (a frail body next to an elite); the bot sweep (§7) catches the worst. (4) First-evening and calibration tests assume fixed spots; they move to fixed-token boards or assert on the drawn spots.

## 4. Contracts

**Provides**
- *Data (HC-W0):* `ApprenticeDef { id, name, token, look: { hue: ApprenticeHue, shape: TokenShape }, hp, move, action: BasicActionId, lean: { trained, gifted }, habit: HabitId | null, starterPage: string, blurb }`; `APPRENTICES`, `APPRENTICE_IDS` (registry order), `ApprenticeId`; `BasicActionId = 'shove' | 'pull' | 'hop' | 'swap'`; `HabitDef { id, line, kind: 'lattice' | 'body', leansOn: RuneId | null }` and `HABITS` (AH fills the new ones); `RECRUITS` stub file for RC.
- *Profile (HC-1):* `household: { members: ApprenticeId[]; slots: [ApprenticeId | null, ApprenticeId | null, ApprenticeId | null] }`, `ink: number`, `lattices`/`proof` keyed by household members. Operations: `joinHousehold(p, id)` (idempotent; bench, starter page, empty proof, current ink), `inHousehold`, `setSlot(p, slot, id | null)` (refused during a trip, no duplicates), `tripParty(p)` (filled slots in order). Save version 9.
- *Trip (HC-4):* `Trip.party: ApprenticeId[]` (1–3, fixed at `startTrip`), `hp`/`charges` keyed by it; a wipe is all of `party` down.
- *Boards (HC-2):* notation `P`, `BoardSpec.starts: Coord[]`, `checkRoom(layout)`, `placeParty(board, lineup, seed)`, `BattleSpec.lineup` and `startSeed`, `startSeedFor(trip, encounter)`. Room data is ASCII with `P` (the format CN, SM, DK and the district plans author in).
- *Battle (HC-2/HC-4):* `MemberUnit.def: ApprenticeId`, `MemberUnit.action: BasicActionId`, `lean.habit` as today; AH reads these.
- *UI (HC-6/HC-7):* `ApprenticeToken.svelte` (letter, hue, shape, sizes for board/strip/ledger); shelf cards render only `ApprenticeDef` and `HabitDef` fields, so RC's entries appear without UI work.

**Consumes**
- Nothing blocking. FD's arrival pipeline and AH's actions are not needed for this build. *Assumes* DK-W0 does not move the trip-party code in `run.ts` before HC-4 lands (or carries `Trip.party` across); and that RC banks a recruit through `joinHousehold` via DK's offer-kind extension rather than editing `returnHome`.

## 6. Verification

- **Engine tests:** placement determinism and subsets (`tests/engine/rooms.test.ts`); notation `P` parse/serialize and error cells; `checkRoom` on all room data; save v9 round trip and the older-version clear; `joinHousehold`; trips of size 1–3 through win, wipe, reload replay, doorway and banking; the lock solvable from every point. Existing scenario tests keep fixed `D`/`S` boards and must stay green unchanged.
- **Bot and fuzz:** extend `tests/sim/bot.ts`/`fuzz.test.ts` to run every room variant with parties of 1, 2 and 3 over ≥50 seeds: no throw, no event-cap overrun, no unit spawned on a blocked tile, and a per-room win-rate table at party size 2 compared with the pre-change baseline (a room that drops sharply gets its points re-laid).
- **Phone (375×812, `verify` skill):** Study shelf with the pair, with three slotted and a bench (test profile), bench sheet open, a drag in progress; Combat on a converted 6×8 room with three members, a Lab 7×9 board and a 5×6 board with one; threshold with one apprentice; trip page ledger tokens; light and dark. Svelte autofixer on every changed component.

## 7. Open questions for the player

1. **The one-apprentice trip:** party.md calls it a pure challenge. Should Set Out show a quiet line ("going alone") when fewer than three are slotted, or say nothing? *Default:* a single quiet line, no warning.
2. **Ink after P6:** an ink pick now raises every page. Keep the reserve at its current size and see if pages get too long, or halve it now? *Default:* keep it and tune by playing.
