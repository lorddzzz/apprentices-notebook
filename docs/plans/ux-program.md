Each plan has its own `-plan.md` and `-briefs.md`; one status file and one log serve the whole program (`ux-program-status.md`, `ux-program-log.md`, created when the build starts, per the `implement` skill).

## 1. Settled (do not reopen during the build)

- Direction B (lamplit study, rainy night city) with the notebook look at home; premium 2D; fight readability is a hard constraint (five layers, flat tactical overlay never themed).
- Art route: bespoke raster by Codex with GPT image models; vector for UI chrome, icons, the tactical overlay and rune glyphs.
- Fight camera: overhead square ground, high 3/4 standing figures (~1.3 cells tall, short down-right shadow, feet anchored to the cell).
- Map: the owner's hand-drawn map, raster illustration plus a vector state layer.
- Web fonts ship, self-hosted and precached (OFL). Sound, dark mode and a full accessibility pass are out (BL-42, BL-75 stay; contrast, 44 px targets, reduced motion are in, they are L4 standard).
- Rules, content and balance are frozen. Copy changes only where a layout needs them. No save-format change unless a plan states it as a Proposal (see D-list).
- The art bible on the board (§7, v1.0) is the style authority; `docs/art/style-sheet.md` (UA-1) transcribes it into the repo and wins over the board once merged.

## 3. Cross-plan contracts (pinned here; plans quote them, do not redefine)

**C1 Tokens** (UF Pack 0a provides; everyone consumes). `src/ui/theme.css` stays the one token file, reorganised in sections. Names:
- Type: `--font-serif`, `--font-script`, `--font-hand`; scale `--type-xs|sm|md|lg|xl|title`; `--smallcaps` utility class `.label` (no mono in player UI; `--font-mono` kept for dev pages only).
- World palettes: `--home-*` (wood, wall, lamp, paper, ink), `--city-*` (night, wet stone, rain light). A screen declares its world with `data-world="home|city|system"` on its root.
- District light: `[data-district="<id>"]` sets `--district-dark|mid|light` from the bible swatches (board §7). Only scene chrome and art tint read these.
- Meaning colours, identical in every world and district: `--danger` (red, danger only), `--gold` (firsts and discoveries), rune-role hues, apprentice hues. Overlay tokens `--overlay-*` are **never** overridden under `[data-district]` or `[data-world]` (a lint-style test asserts it; R25 adds a source test on the overlay component files and rendered colour/greyscale checks).
- Spacing 4/8/16/24/32, `--tap: 44px`, `--radius`, elevation `--shadow-1|2`, motion `--dur-quick|base|held` (250 ms / 400 ms / 800 ms by default, scaled by the Motion pref).

**C2 Art registry** (UF provides the code; UA fills the files). Shipped assets live at `src/assets/art/<family>/<scope>/<subject>[-<state>].webp`, `family` ∈ `scenes|tiles|props|units|portraits|foes|map|ui-plates|crests|finds` (FX sprites, if any, are `props/shared/fx-*`), `scope` = a district id, `home`, `city` or `shared`. `src/ui/art/registry.ts` discovers them with `import.meta.glob` (no hand-kept list), exposes `artUrl(id: ArtId): string | null` where `ArtId` is the path without extension, and `<ArtImage id fallback>` renders the art or the fallback snippet. **Every screen must render correctly with zero art present** (placeholder first). Adding art is therefore a pure file drop; UA packs never edit code. **Public metadata (R26):** the build also derives `artMeta(id)` = `{ w, h, bytes, bbox?, slice?, role }` from the sidecars (actual shipped size, bbox in master pixels, slice insets in source pixels, bytes); consumers (UT offsets, UH slice insets, Gallery byte counts) read it. Prompts, references and masters never enter the client bundle.

**C3 Sidecars and masters** (UA). Each shipped asset has `art-src/<same path>.json` (screen, district, subject, crop and focal area, angle, light, palette, model, full prompt, reference images, generation id or seed when exposed, date) and a lossless master `art-src/<same path>.master.webp`. The sidecar also declares the asset's **role** and pixel size. Size and alpha rules are per **role**, not per family: `tile-opaque`, `material-overlay-alpha`, `figure`, `boss-figure`, `portrait`, `card`, `strip`, `scene`, `map-plate`, `map-patch-with-bbox`, `nine-slice` (R10/UF-D2). `pnpm art:check` (UF) validates the decoded file against its role rule and fails on a shipped asset without a sidecar, a missing or role-inconsistent master record, a size that breaks the role rule, real transparency where the role forbids it or missing alpha where it needs it, an out-of-bounds bbox, or a scope over budget. **Master storage (D4, changed after review):** the lossless master is the accepted native-resolution source of each shipped asset, committed only if the UA pilot's projection allows; rejects and contact-sheet candidates stay outside Git.

**C4 Sizes** (from the bible): tile masters 128×128 (cell ~58 CSS px at 375); unit and foe figures on a 128×176 transparent canvas, ground-contact point declared in the sidecar and placed by the processor at the baseline (y = 160) so they lap ~1/3 cell into the row above; portraits 192×192 (shown at 48–96 px) plus a 48×48 greyscale-checked silhouette crop; scene strips 750×128 or 750×N per the §6 frames; full-bleed 750×1624; map: a registered 750×3800 plate (1:1 @2x of the existing 1900 CSS px map layer, `MAP_PAGE_HEIGHT`; UT-D8) is the generation frame; the shipped map is cropped alpha patches with bbox in master pixels (R19). Shipped WebP quality 80 (painted) unless a pack's review says otherwise.

**C5 Budget.** Precache everything (offline is a PWA promise). First-pack measurement sets the real number; until then: shared + home ≤ 4.5 MB (UA-D13), each district ≤ 1.5 MB, map ≤ 0.8 MB, total ≤ 15 MB. `art:check` prints per-scope totals.

**C6 Motion and playback** (FT provides). The chain readout, numbered step markers (`StepMarker` from UF), held beats for bursts, compounds and firsts, tap to speed up, Skip to result, reduced motion = cross-fades only. Timings come from `--dur-*` / a TS mirror scaled by the Motion pref (`normal|quick`, a device pref in localStorage, not in the save). Transitions (UH) and end-of-trip scenes (UT) use the same pref and the same skip rule.

**C7 Shared components** (UF provides, API frozen at UF's Pack 0a): `AppHeader` (world, title, back or crest, subtitle, right slot for icons, ⋯ always last), `ActionButton` (`primary|secondary|quiet`, one primary per screen), `Sheet` (existing API kept, restyled: handle, title row, ✕, swipe and tap-out), `Unseen` (dashed frame + ??? or silhouette), `StepMarker` (number, gold variant), `MenuSheet` (⋯), `Toasts` (small facts only), `Card` (paper card, sizes to content). Screens never hand-roll these.

**C8 Screen state fixtures** (UF provides): every screen and the states in the plans' Done-when cells can be opened at 375×812 from a fixture (`tests/fixtures/saves/` plus a dev-only `#/fixture/<name>` loader or equivalent), so a `verify` run never needs a live play-through. Late states (Threshold, Crossroads, Cleared, Wiped, Drawing table, Handover, Credits) get fixtures first.

## 5. Routing and models (execution)

Per the `implement` skill, with one addition for art:
- **Claude packs** (all `.svelte`, `.ts`, `.css`): Sonnet 5.5 high by default; Opus 5.5 high for UF Pack 0a/0b/0c and the playback pack (no template to follow). They run the Svelte autofixer and, for new interactions, the 375×812 phone check.
- **Codex art packs**: GPT-6.2 Sol high via Whiteboard's Git-enabled spawn (`git: true`), branch `art/<pack>`. A pack generates, cuts out, resizes, exports WebP, writes sidecars and masters, renders a contact sheet (`docs/art/contact/<pack>.png`), runs `pnpm art:check`, and commits. It owns only C2/C3 paths. Review: the orchestrator opens the Gallery art page (UF) at 375×812 and checks the bible's acceptance list (board §7 "Review at 375 × 812"). One return per pack, then regenerate with a new brief.
- **Design windows** (Opus high): writing and revising briefs, Wave 0 reviews, gate follow-ups.
- **Plan files must be committed on `main` before any Git-enabled worker spawns** (R24): a worker sees only its base commit. At build start the orchestrator verifies every input a pack lists exists at that SHA.
- Two or three packs at a time, normally one Claude code pack + one Codex art pack + one more Claude pack on disjoint files.

## 6. Shared verification

- Every UI task: states listed as fixtures (C8), screenshots at 375×812; greyscale screenshot for every fight state.
- `art:check` in **both** `check` and `check:fast` once UF Pack 0b merges (fast, file-only; R25).
- Per phase end: `pnpm check`, a full-loop phone run of what changed, one `code-review`.
- Readability tests that are code: overlay tokens are not overridden by any district or world selector; tap sizes (≥ 44 px) are checked on the 375×812 fixture screenshots, since Vitest runs without a DOM.
